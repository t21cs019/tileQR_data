# EPYC 7543 の追加計測（τ の確認）の検証依頼

あなたの仕事は、EPYC 7543 の追加計測の結果が、下の「検証する主張」を支えているかを、**反証するつもりで**判定することです。
報告は 11-11 のゼミの前に使います。新しい計測はせず、手元のデータだけで判定してください。

## 背景（これ以上の背景資料は読まなくてよい）

tile QR（PLASMA）で、コア数が多いと小さい nb の性能が理論モデルより落ちる。既存データの読み直しから、次の式の第2項が欠けていると推定した。

```
時間 = W / (r0 · p · A_k · E_k(nb) · η(nb)) + タスク数 · τ      W = 4/3·size³
τ = タスク1個ごとの余分な時間。τ = a·p（a は全機種共通の定数）
```

既存データからの値：EPYC 7543（p=32）は τ = 2.18 µs（τ/p = 0.068）、EPYC 7702（p=64）は 4.56 µs（0.071）、Xeon 4214（p=12）は 0.85 µs（0.071）。1機種ずつ抜く交差検証では a ≈ 0.09 µs。
今回の計測は、この推定を同じ機械の中で確かめるためのもの。

## 検証する主張

各項目を「支持 / 一部支持 / 反証 / 判定不能」で判定し、根拠の数値を示してください。

1. **空のタスクの τ は p に比例する**（τ = a·p で a ≈ 0.07〜0.09 µs）。切片が要るか、p=1 を含めてよいか、タイル数や `work_ns` で変わるか。短い条件の動作確認では p=4 が 0.9〜1.2 µs で、予測 0.36 µs より大きかった。
2. **QR の小さい nb の遅さは「タスク数 × τ(p)」で説明できる。** 同じ機械で p を変えた QR の余分な時間と、空のタスクの τ が量として合うか。合わないなら何倍違い、どの nb・p か。
3. **τ は 1か所を順番に通る直列の時間である**（各コアが払う並列のオーバーヘッドではない）。以前は「1機種の中では区別できない」としていた。p を変えた今回のデータで区別できるようになったか。
4. **libgomp と libiomp5 で τ の大きさと p への依存が違う。** 違うなら、plasmatest の結果を解釈するときどちらの値を使うべきか。
5. **同じプロセスで2回目以降の分解は速い**（1回目だけ一定の時間が余分に入る）。その時間の大きさ、size・nb への依存、固定あり（close）と固定なし（none）の差。

主張ごとに、上の式や解釈以外の説明も考えてください。特に下の「交絡」が結論を変えないかを確かめてください。

## 交絡（まだ確かめていない）

- **空のタスクのばらつきが大きい。** 72 条件中 42 条件で max/min > 1.2。最大は libgomp・p=1・タイル 64 の 2.13、libiomp5・p=4・タイル 64 の 1.92。タイル 64 は実行時間が短い
- **`submit_sec / total_sec` の中央値が、libgomp は p ≥ 2 でほぼ 1.0、libiomp5 は 0.74〜0.91。** `submit_sec` をそのまま「タスク生成の時間」と読むのは危ない
- **libiomp5 の p=1 の τ が 0.076 µs と極端に小さい**（p=2 は 0.96 µs）。p=1 だけ別の経路を通っている可能性がある
- **空のタスクは実際の QR のタスクと長さが違う。** `work_ns` は 0 と 1000 だけで、nb 32 の実タスク（µs のオーダーより長い）より短い。取り合いの強さが違う可能性がある
- **p と L3 の個数が一緒に変わる。** close 固定で L3 は4コアごとなので、p=4,8,16,32 は L3 が 1,2,4,8 個
- **クロックが p で変わりうる。** `meta.txt` の平均 MHz は計測の前後の 2025〜2773 MHz の値しかなく、計測中の値は分からない
- **QR のカーネルが MKL か OpenBLAS か未確定。** plasmatest の見出しは MKL だが `libopenblas.so` も読み込まれ、ldd の順番では MKL より前。libgomp と libiomp5 も両方読み込まれている。どちらの OpenMP が QR を動かしたかも、ログだけでは確定していない
- **thread-scaling の ib は nb/4 に固定。** 以前の QR の当てはめは ib を振った最高値を使っている
- **他のユーザーのジョブがなかったことは確かめていない。** `uptime` は「1 user」、計測前の load average は 0.14
