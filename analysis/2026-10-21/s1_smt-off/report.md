## 0. 要点（スライド用）

- **絞り込むと、崩れるパターンは「多コア・小行列」の1種類にほぼまとまる。** 性能比 95% 未満は57条件中10条件（全構成版は85条件中26条件）。全構成版でもう1つの崩れ方だった「予測 nb が大きすぎて 512 に張り付く」型は、HT 構成を外すと3条件（92.5〜92.6%）しか残らない。
- **崩れる10条件のうち5条件は p ≥ 24（EPYC 7702 / EPYC 7543）で、W/(pD) < 1.5 の6条件中5条件が 95% 未満。** どれもモデルが nb を小さく予測しすぎる（実測最適 / 予測 ≈ 1.4〜2.4）。p ≤ 12 の47条件は平均 97.1%・最低 92.1%。
- **「並列度不足の条件で崩れる」は当たっているが、原因はモデルの想定と逆向き。** DAG の厳密スケジューリングで η を計算しても、多コア側の予測は改善しない。実測は、コアを遊ばせてでも大きいタイルを選んでいる。
- **D = 30N − 34, W = 4N³ は、Bouwmeester 型の依存なら N = 2〜64 で厳密に一致する**（データに依存しないので全構成版と同じ結果）。PLASMA 実装の DAG は WAR 依存が加わって 30N − 28。
- **c は理論値 √7.5 に固定し、k だけフィットするのが有望。** 13構成すべてで LOAO をやり直すと、現行（c, k 両方フィット）が平均 96.3%、c = √7.5 固定が 96.5%。全条件フィットの c は 2.652 になり、√7.5 = 2.739 との差は 3%。完全に計測なしの定式は、どれも現行より悪い。
- **注意：p ≥ 24 は EPYC 7702 と EPYC 7543 の2機種（どちらも AMD Zen）だけ。** 「多コアで崩れる」は2機種のデータで言っていることになる。

### 2.3 追加の確認（A-4）

- **探索範囲の端への張り付き**：
  - 予測 nb が**上限 512** に張り付くのは7条件：i3-10100 / i5-7400 / i7-7700 / i3-7100 / i3-8100 の各 8192、i5-8500 16384、E3-1220v3 8192。実測最適は 392〜480 と端に近く、性能比は 92.6〜96.2%。E3-1220v3 以外は 95.5% 以上で、COVERAGE でも「走査端で切断」。真の最適が 512 より上にある可能性もあり、走査範囲の上限そのものの影響が混ざっている。
  - **下限 32 への張り付きは無い**（予測の最小は EPYC7702 s1 1024 の 56〜60）。
- **崩れる条件での山のずれ方**：多コア・小行列ではすべて**モデルの山が実測より左（nb を小さく予測しすぎ）**。`fig_a_curves.png` の左2枚のとおり、実測は最適 nb を過ぎてからの落ち方がモデルより緩やか。EPYC7543 2048 は nb ≈ 120〜330 が台地で、nb ≈ 342 で急落する。2048/342 ≈ 6 で、ちょうどタイル数 N が 7 → 6 に変わる境界にあたる。N が小さい領域では、タイル数の整数性が曲線の形に直接出ている（観察）。p ≤ 12 の崩れ（同右端、i7-6900K 1024）は逆に山が右にずれている。
- **2ソケット・HT 有効**：今回は対象外。全構成版では、2ソケット EPYC 7702（128コア）は多コア側と同じ向きでさらに強く崩れ、HT 有効は逆向きに崩れた。
- **計測品質との重なり**：(1) 群の EPYC7702 s1 1024 は COVERAGE で 95%帯が退化している。EPYC7543 1024/2048 は帯が健全（41点・37点）だが、`kurzak.py` は「タスクオーバーヘッド支配で GFlops が異常に低い」として除外対象にしている。`fold_constants.py` も今回の分析も除外していない。

### 2.4 言語化（A-5、データからの観察として）

1. HT 無効・1ソケットでは、モデルは **W/(pD) ≳ 1.5（実測最適 nb でもコアあたり1.5本分以上の仕事が DAG にある）条件で平均 97% の性能比**を出す。崩れはほぼ **W/(pD) ≲ 1.4 の多コア・小行列**（今回のデータでは p = 32, 64 の EPYC で size ≤ 8192）に限られる。
2. その領域では、モデルは**並列度を確保するために nb を小さくしすぎる**。実測は、コアを遊ばせてでも大きいタイルを選んでいる。単体 DTSMQR の E(nb) では、多コア・少タスクの条件で小さい nb のコストを表しきれていない可能性が高い（オーバーヘッドやメモリ帯域が候補。未検証）。
3. 並列度が十分な p ≤ 12 では、nb のずれは大半が ±1.3 倍以内（最大は R5-7400F 4096 の 1.76 倍）で、性能比は 92% 以上。主な要因は、大行列で最適 nb が頭打ちになること（E3-1220v3, Xeon4214）と、走査上限 512 での打ち切り。
4. p ≥ 24 の根拠が2機種（どちらも AMD Zen）だけなので、「多コア一般の性質」か「この2機種の性質」かは、まだ区別できない。

図：`fig_a_perf_vs_parallelism.png`（a）、`fig_a_nbratio_vs_x.png`（b）、`fig_a_curves.png`（c：EPYC7702 s1 1024、EPYC7543 2048、i7-6900K 1024）

**クリティカルパスの中身（B-3）**

- N = 3（56）：GEQRT(0,0)[4] → TSQRT(1,0)[6] → TSMQR(1,1)[12] → TSMQR(2,1)[12] → TSQRT(2,1;k=1)[6] → TSMQR(2,2;k=1)[12] → GEQRT(2,2)[4]
- N = 4（86）：GEQRT(0,0)[4] → TSQRT(1,0)[6] → TSMQR(1,1)[12] → TSMQR(2,1)[12] → TSMQR(3,1)[12] → TSQRT(3,1;k=1)[6] → TSMQR(3,2;k=1)[12] → TSQRT(3,2;k=2)[6] → TSMQR(3,3;k=2)[12] → GEQRT(3,3)[4]

経路は L 字形をしている。ステップ 0 で列1を TS の連鎖で縦に下り（TSMQR × (N−1) = 12(N−1)）、そのあと最下行をステップごとに TSQRT + TSMQR（18）で横に進む。合計は 4 + 6 + 12(N−1) + 18(N−2) + 4 = **30N − 34**。N が1増えるごとに、縦に +12、横に +18 で +30。

## 5. 確認事項

**今回の絞り込みに固有のもの**

1. **p ≥ 24 は2機種（EPYC 7702 s1 = 64コア、EPYC 7543 = 32コア）だけで、どちらも AMD Zen。** 「多コア・小行列で崩れる」と「c を √7.5 に固定してよい」の多コア側の根拠は、この2機種に依存している。p = 16〜32 帯の Intel 多コア機（例：Xeon 4214 は12コアで止まっている）があると切り分けられる。
2. **EPYC 7702 s1 を「1CPU」に含めた。** 2ソケット機の片ソケットを numactl で固定した計測なので、1ソケット機とは L3・メモリの構成が少し違う可能性がある。外すべきかは判断が要る。
3. **HT を外すと「上側の頭打ち」の論点はほぼ消える。** ただし E3-1220v3 8192 と Xeon4214 s1 16384 に弱く残っており、HT だけの現象ではない。
4. 走査上限 512 に予測が張り付く7条件は、E3-1220v3（392）を除くと実測最適も 456〜480 で、COVERAGE でも「走査端で切断」。真の最適が 512 より上にある可能性があり、性能比の上限を下げている。

**全構成版から引き継ぐもの**

5. 現行モデルの定義が3通りある：vault は第4世代、tileQR_bench の正典実装は別の第4世代定数、指示書と `fold_constants.csv` は第3世代（c = 2.564, k = 1.352）。どれをゼミの「現行」とするかの確認が必要。
6. 導出（W = 4N³, D = 30N − 34, Brent）は vault に記述が無い。D は論文の依存なら正しいが、PLASMA 実装の DAG では 30N − 28。条件は N ≥ 2 で成り立つ。
7. `kurzak.py` が除外対象にしている i3-7100 全体、EPYC7543 1024/2048、i5-8500 8192 を、`fold_constants.py` も今回の分析も除外していない。EPYC7543 1024/2048 は崩れた条件に入っている。
8. β：中間40は `fold_constants.py` のハードコード値（出典未確認）を使った。SSRFB から再計算した値とは数 % ずれる。E3-1220v3 の β は SSRFB 2本の平均。
9. EPYC7702 s1 1024/2048 は COVERAGE で 95%帯が退化している。
