## 1. 結論

- **QR の「τ = a·p」は反証。** p = 1 を基準にすると、nb 32 の余分な時間は p = 4, 8, 16, 32 で 2.0 / 2.4 / 2.8 / 3.4 µs/タスク（推定）。p が 8 倍で 1.6 倍にしか増えず、nb 64 でも同じ（1.7〜3.3）。ただし **p = 2 だけは「一定」にも合わない**（6.0〜11.3 µs。size 8192・nb 32 は p = 1 より遅い）。
- **空タスクの τ（中身 0）は、中身を入れるとそのままは足されない。** libgomp は 0.2 µs まで消える（直列）。libiomp5 も p ≥ 8 で 0.4〜1.2 µs に減るが 0 にはならない。実タスクの長さ（20000 ns）での余分な時間は QR の推定値の 16〜78% しかなく、**空タスクでは QR の余分な時間を再現できていない。**
- libgomp の p = 32 は2つではなく **4つの値**（3.8 / 4.5 / 5.8 / 6.1 µs）に分かれる。libplasma は `/usr/local/lib` と `~/Library` で **md5 が違う**（大きさは同じ）。

## 3. 11-10 の判定表から変わるもの

- **主張 2（QR の遅さ ＝ タスク数 × τ(p)）：一部支持のまま、中身が変わる。** 「タスク数に比例する」は強まった（p = 1 基準でも nb 32 と 64 が同じ）。「p への依存は決まらない」は決まった：比例ではなく、p ≥ 4 で 2.0 → 3.4 µs とゆるやかに増える。一方「libiomp5 の空タスクの 1.0〜1.2 倍で合う」は弱まった：合っていたのは中身 0 の値で、中身を実タスクの長さにすると空タスクは QR の 16〜78% しか出ない。
- **主張 3（τ は直列の時間）：判定不能 → 空タスクについては「libgomp は支持、libiomp5 は一部支持」。QR については判定不能のまま。** 単純な直列の式（全時間 = max(タスク数·τ₀, カーネル/p)）は QR では合わない：nb 64・p = 16 はカーネル/p が 3.4 µs（推定）、nb 32 の頭打ちが 3.7 µs なのに、全時間は 5.66 µs。QR のデータは足し算の式のほうに合う。
- **主張 1（空タスクの a ≈ 0.07〜0.09）：反証のまま。** 追記：libgomp の p = 32 は4つの値で、今回の中央値は 4.50 µs（11-10 は 5.59）。プロセス数が少ないと中央値が群の引き方で動く。
- 主張 4 は判定は変わらない（「どちらを使うか」は 11-10 の `LD_DEBUG` で libiomp5 と決まった）。主張 5 は今回のデータでは確かめていない。
