# 不老・弐 QR の予測 nb での性能比を、集計3通りで出す（2026-11-17）

## 1. 結論

**3通りのどの集計でも「当てはめなしのモデルは不老・弐に合わない」という結論は変わらない**（予測の nb での性能は実測の最大の 1〜4%、size 8192 だけ 20〜24%（MaxIB の A・β では 6〜10%）。予測の最適 nb 32〜128 はどの集計の実測の最適 nb 176〜408 とも離れている）。

性能比 = 実測（予測の最適 nb、ib について最大）/ 実測の最大（全 nb）。各集計の曲線の中で割る。

**A = 99.7、β = 124（ib = nb/8、11-11 の主の値）**

| size | 予測の最適 nb | 速い水準 | 遅い水準だけ | 5回の平均 | 実測の最適 nb（速い／遅い／平均） |
|---|---|---|---|---|---|
| 1024 | 32 | 0.029 | 0.035 | 0.024 | 176 / 200 / 184 |
| 2048 | 40 | 0.016 | 0.015 | 0.014 | 208 / 188 / 188 |
| 4096 | 72 | 0.034 | 0.032 | 0.030 | 220 / 220 / 212 |
| 8192 | 128 | 0.244 | 0.208 | 0.204 | 400 / 408 / 408 |

**A = 95.0、β = 68（MaxIB、11-11 の感度の値）**

| size | 予測の最適 nb | 速い水準 | 遅い水準だけ | 5回の平均 |
|---|---|---|---|---|
| 1024 | 32 | 0.029 | 0.035 | 0.024 |
| 2048 | 36 | 0.012 | 0.011 | 0.010 |
| 4096 | 64 | 0.024 | 0.023 | 0.022 |
| 8192 | 104 | 0.098 | 0.059 | 0.058 |

**集計の定義と出典**（すべて `analysis/2026-11-10_flow2-sweep-check/report.md` の「2. C. 2つの水準」の「用語」と「C6. 集計の方法」）

- **速い水準**：`add_baseline`（同 `scripts/common.py`）の base。点 (nb, ib) の 3×3 近傍の全実行（最大 45 回）のうち、近傍の最小時間の下側四分位から 7 ms 以内（size 8192 は 4% 以内）のものの中央値（時間）を GFlops に直したもの。C6 で推奨とされた集計で、11-11 の p.9 と同じ
- **遅い水準だけ**：ex = 時間 − base が 6 ms を超えた実行（「用語」の「ex > 6 ms を遅い水準とした」）だけを残し、点ごとに GFlops を平均したもの。速い水準の実行を除外した集計。遅い実行が無い点は外した
- **5回の平均**：点ごとの 5 回の GFlops の平均（C6 の mean、`ingest.py` と同じ。11-11 の感度の値と同じ）
- どれも、点ごとの値を (size, nb) ごとに ib について最大を取った曲線で比べる（11-11 の `c_qr.py` と同じ）

## 3. 手順

1. `scripts/a_curves.py`：点ごとに集計（速い水準・遅い水準だけ・5回の平均と、感度2つ）し、ib について最大 → `data/a_points.csv`、`a_curves.csv`、`a_counts.csv`
2. `scripts/b_ratio.py`：予測の最適 nb、実測の最適 nb と 5% 以内の範囲、性能比 → `data/b_summary.csv`。11-11 との突き合わせ `b_check_1111.csv`。実測/予測の nb 依存 `b_ratio_by_nb.csv`。図 `fig_b_ratio.png`

**感度（結論は同じ）**

| 1024 | 0.054 | 0.023 |

（A = 99.7、β = 124。MaxIB の値は `data/b_summary.csv`）

**実測/予測（= η_eff/η理論、A = 99.7・β = 124）の nb 依存**：3通りの集計とも nb 64 で 0.004〜0.028、nb 128 で 0.057〜0.176、nb 448 で 0.63〜0.93 と、nb とともに上がる（`data/b_ratio_by_nb.csv`）。遅い水準だけ・5回の平均では nb 512 で下がる（例：size 1024 で 0.63 → 0.59、0.72 → 0.62）。速い水準では下がらない（0.93 → 0.95）

## 気になる点・判断を保留したこと

- **予測の nb（32〜128）では、「遅い水準だけ」はほぼ「5回の平均」と同じ値になる。** その nb は report.md で base が当てにならないとされた範囲（nb < 96 / 160 / 192）で、base が低めに出るため、ほぼすべての実行が遅い水準と判定される（範囲外の遅い割合 84〜100%）。予測の nb での「遅い水準だけ」の値は、遅い水準を正しく選んだ結果ではない。代わりに base + ΔT（判定をしない版）も並べた。どちらでも性能比は 0.02〜0.05（size 8192 は 0.21〜0.25）で結論は変わらない
- size 8192 は report.md C 節で 2 つの水準が分かれない（判定できない）とされている。8192 の「遅い水準だけ」は ex > 6 ms で機械的に分けた値
- 「遅い水準だけ」の点ごとの値は遅い実行の数（0〜5 回）で精度が違い、ib の最大を取ると高く出た点を選びやすい（曲線が速い水準よりぎざぎざ。`fig_b_ratio.png`）
- nb 512 で遅い水準だけ・平均・中央値が下がり、速い水準だけ下がらないのは、base が 3×3 近傍でならすため（nb 512 は格子の端）と考えられるが、確かめていない。性能比には影響しない
- どの集計を採るかは決めていない（ゼミで相談）
