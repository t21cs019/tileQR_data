# full_search_threads — 学部時代の dogwood フルスイープのスレッド数推定

`attic/Full_search_dgeqrf/`（i7-6900K、dgeqrf size4096、threads 列なし・
スレッド数不明）を、2026-08-30 の `dogwood_s1_smt-off` th=8 実測
（size4096、5反復の平均）と突き合わせた。

**位置づけ: 参考情報。** 当時の PLASMA ビルド / BLAS / メモリ構成の記録が
無く、水準の比較はそれらと交絡する。この結果がどちらに転んでも
attic のデータを raw/ に上げる根拠にはしない
（i5-7400 で「形状は健全でも記録が無ければ落とす」とした基準と同じ）。

再現: `python studies/full_search_threads/compare.py`

## 結果（2026-09-01）

ib 最適化後の nb 曲線、共通 121 点（nb 32-512）:

| 指標 | 値 |
|---|---|
| 比（旧 / 新th8）の中央値 | **1.163** |
| 比の範囲 | 1.070 - 1.309 |
| ピーク | 旧 251.1 GFlops (nb=276) / 新th8 217.2 GFlops (nb=280) |
| 形の相関 | **0.9934** |

nb 帯域ごとの比: 32-128 で 1.217、132 以降はほぼ一定の 1.16。

## 読み

**判定できない。** 2つの証拠が別方向を向いている。

- **形はほぼ同一**（相関 0.9934、最適 nb は 276 vs 280 で格子1刻み差）。
  スレッド数が違えば並列度が変わり形がずれるはずなので、
  これは「同じ th=8 だった」ことを示唆する。
- **水準は旧が +16%**。同じ th=8 なら水準も揃うはずで、この差は
  (a) 当時は SMT で th=16 だった、(b) 当時のビルド / BLAS が速かった、
  のどちらでも説明できてしまう。Broadwell-E の SMT がタイル QR に
  効かせる相場（0〜15%）とビルド差の相場（±20%）が重なっていて分離できない。

## 決定打になる実験

**dogwood を smt-on にして th=16 の size4096 を1本測る。**
th=8 と th=16 の実測が両方揃えば、旧データの水準がどちらに乗るかで
（同一マシン・同一ビルド内の比較として）はっきり切り分けられる。
1本 = 3963 点なので手間は小さい。

それでも「当時のビルドが違う」交絡は残るため、判明後も扱いは
参考データ止まり。`attic/README.md` の昇格の基準を参照。
