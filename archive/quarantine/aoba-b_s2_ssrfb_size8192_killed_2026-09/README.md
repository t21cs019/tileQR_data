# aoba-b_s2_smt-off ssrfb size8192 — 2026-09-05計測分（ジョブがSIGKILLされ未完走）

## 何のデータか

AOBA-B の `aoba-b_s2_smt-off` の ssrfb（カーネル単体スイープ）、size8192、
2026-09-05 計測、par043。ジョブログ: `~/research/ssrfb/ssrfb_aoba_s2.o271737`
（このリポジトリ外）。

## なぜ隔離したか

このジョブは par043 の1ノード上で size1024/2048/4096/8192 の4スイープを
NUMAサブ領域ごとに並行実行していた（`[START] size=1024 cpu=0 node=0` ...
`size=8192 cpu=96 node=6`）。size1024/2048/4096 は完走したが
（`[DONE] rc=0`）、size8192 の完了ログが無いまま

```
%NQSV(INFO): Batch job received signal SIGKILL. (Exceeded per-req elapse time limit)
```

でジョブ全体が強制終了された。実際 `aoba_s2_smt-off_ssrfb_size8192_nb32-512_t1.csv`
は 12,940 行しかなく、他の3サイズ（いずれも19,816行 = 5トライアル×3963点+header）
と比べて明らかに不完全（約65%で打ち切り）。

## 再利用の条件

**そのままでは使えない。** 5トライアルのうちどこまでが完全なトライアルか
（境界は `(nb,ib)` の再出現で判定可能）を確認すれば部分的に使える可能性は
あるが、未検証。再計測が最も確実。

## 再計測時の注意

同じ4サイズ並行実行の構成を使うなら、size8192 だけ別ジョブに分けるか、
時間制限を緩めること。他3サイズ（size1024/2048/4096）は同じ構成で
完走できているため、構成自体に問題があるわけではなく、size8192の
所要時間が結合ジョブの時間制限を超えたと考えられる。
