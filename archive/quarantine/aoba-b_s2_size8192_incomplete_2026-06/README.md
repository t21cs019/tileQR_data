- `par006_size8192_nb20-512_t1_20260615_071222.csv`

## なぜ隔離したか

**測定条件そのものは無効ではない**（AOBA-B s1 の16コア問題や i5-7400 の
メモリチャネル問題とは性質が異なる）。5トライアルとも揃っており、
95%性能帯の健全性も「ok」（帯内2点、ノイズ比0.089程度）。

問題は **nb の走査範囲が計画に届いていないこと**。実際の走査は nb 20-508
（step 8）までで、`spec/plan.yaml` が要求する nb 32-512 の格子を約97%
しか満たしていない。5反復・trials は足りているが、この状態を「done」として
扱うと格子の穴があるまま完了条件を満たしたことになってしまう
（`docs/COVERAGE.md` では `partial` 表示。詳細は
`docs/design/coverage-and-plan.md` の「COVERAGE.md が出すもの」）。

2026-09-05、AOBA-B s1 の隔離作業を機に、このデータも走査範囲を完全に
満たす形で再計測することとし、いったん退避した。

## 再利用の条件

**部分データとしてなら使える。** nb 20-508 の範囲内では95%帯の判定も
健全（「ok」）で、trials も5本揃っている。ただし nb 512 近辺の挙動を
含む主張（例えばピークが nb=512 側にある可能性）には使えない。
使う場合は「nb 20-508 までの部分走査」であることを明示すること。
