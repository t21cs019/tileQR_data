# i5-7400_s1_smt-off — 2026-06計測分（シングルチャネル計測）

## 何のデータか

i5-7400（Kaby Lake, 4コア/SMTなし）の `i5-7400_s1_smt-off` 系列。
qr_sweep（PLASMA dgeqrf の nb×ib スイープ）、size 1024/2048/4096/8192、
2026-06-24（size8192のみ2026-06-30）計測。

- `i5-7400_size1024_nb32-512_t5_20260624_104705.csv`
- `i5-7400_size2048_nb32-512_t5_20260624_114156.csv`
- `i5-7400_size4096_nb32-512_t5_20260624_162515.csv`
- `i5-7400_size8192_nb32-512_t5_20260630_003200.csv`

もとは `raw_data/i5-7400_s1_smt-off/` にあり、`spec/curation.yaml` の
`i5-7400-qr_sweep-memory-channels` ルールでファイル名を指定して除外していた。
2026-09-05、AOBA-B s1 の隔離作業に合わせて置き場所をディレクトリ移動方式に
統一し、`curation.yaml` のルールは削除した（削除ではなく退避なので、
データ自体はここに残っている）。

## なぜ隔離したか

2026-06-24（size8192のみ06-30）の計測は、実機の DIMM が1枚しか挿さって
いない**シングルチャネル**状態で行われていた。2026-08-31 の実機検証
（DIMM を1枚抜き差しして両構成を比較）で、6月の値がシングルチャネル側と
一致することを確認済み（代表10点の比が平均 1.003、範囲 0.979〜1.016）。

デュアルチャネル化の効果は nb に依存し、nb=32 で +5.9%、nb=448 で +21.4%。
一様なオフセットではないため後から補正できず、最良 nb も 232 → 320 と動く。
したがってこのデータは他機種と比較できず、研究の主張には使えない。

検証の詳細・再現手順は `studies/i5-7400_memory_channel/`。

## 再利用の条件

シングルチャネル構成そのものを調べる目的以外では使わない。
`memory_channels: 1` の条件として扱う場合は、`spec/machines.yaml` の
`i5-7400_s1_smt-off`（現在は `memory_channels: 2`）とは別条件であることを
明示すること。
