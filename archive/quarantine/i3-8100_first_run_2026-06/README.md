# i3-8100_s1_smt-off — 2026-06計測分（初回計測、再計測で置換）

## 何のデータか

i3-8100（Coffee Lake, 4コア/SMTなし）の `i3-8100_s1_smt-off` 系列の qr_sweep
（nb×ib スイープ）、size 1024/2048/4096/8192。2026-06-23（size8192のみ
2026-06-30）計測。

- `i3-8100_size1024_nb32-512_t5_20260623_035907.csv`
- `i3-8100_size2048_nb32-512_t5_20260623_045522.csv`
- `i3-8100_size4096_nb32-512_t5_20260623_100454.csv`
- `i3-8100_size8192_nb32-512_t5_20260630_070716.csv`

もとは `raw_data/i3-8100_s1_smt-off/` にあった。`docs/TODO_REMEASURE.md` の
再計測対象（形状が同コア数群の外れ値）で、2026-09-13〜14 に再計測された
ため、`raw_data/` から退避した。size16384（1トライアルのみ、2026-07-03）は
再計測が無いので `raw_data/` に残してある。

## なぜ隔離したか

再計測と比べて明らかに遅い。原因は**シングルチャネル**とみられる。
計測者の申告では、6月時点のメモリは 4GB DIMM 1枚（DDR4-2400 か 2133）
だった。再計測時の機体は 16GB x2（ChannelA/B、Configured 2400 MT/s、
`dmidecode` 2026-09-19 採取）。i5-7400 の例
（`../i5-7400_single_channel_2026-06/`）と同じ型の問題で、性能差の出方
（size が大きいほど差が開く）も整合する。ただし6月時点の構成を裏付ける
記録は無く、i5-7400 のような DIMM 抜き差しによる実機検証もしていない。

| size | 旧 GFlops (nb*) | 再計測 GFlops (nb*) | 比 |
|---|---|---|---|
| 1024 | 65.3 (152) | 75.0 (148) | 1.15 |
| 2048 | 82.8 (192) | 102.6 (232) | 1.24 |
| 4096 | 97.4 (208) | 121.4 (376) | 1.25 |
| 8192 | 108.7 (224) | 137.1 (464) | 1.26 |

差は size と nb に依存し、一様なオフセットではない。旧データは補正できず、
他機種との比較や研究の主張には使えない。

## 再利用の条件

シングルチャネル構成そのものを調べる目的以外では使わない。
`memory_channels: 1` の条件として扱う場合は、`spec/machines.yaml` の
`i3-8100_s1_smt-off`（現在は `memory_channels: 2`）とは別条件であることを
明示すること。
