# epyc_s1_smt-off size1024 / 2048 — 2026-07計測分（全体に15〜20倍遅い）

## 何のデータか

`epyc_s1_smt-off`（EPYC 7543、threads=32）、size 1024 と 2048 の qr_sweep。
2026-07 に計測し、`raw_data/epyc_s1_smt-off/` から `raw/` に上がっていたもの。
2026-10-27 に再計測したデータと差し替えるため、ここへ退避した（削除ではない）。

| ファイル | 開始 | 中身 |
|---|---|---|
| `epyc_size1024_nb32-512_t5_20260725_110847.csv` | 2026-07-25 | 5周、nb 32-512 / ib 8-nb/2（4刻み）を完走 |
| `epyc_size2048_nb32-512_t5_20260726_011720.csv` | 2026-07-26 | 5周。r5 だけ nb 500 で終わっている |

差し替え先は同じディレクトリの
`epyc_size1024_nb32-512_t5_20261027_080944.csv` と
`epyc_size2048_nb32-512_t5_20261027_095708.csv`（格子は同じ）。

## なぜ隔離したか

**同じ機械・同じ格子の再計測より、全体に15〜20倍遅い。** 5周とも同じ値で
そろっているので、偶然のノイズではない。7月の計測中、ずっと何かが
起きていたとみられる。原因は分かっていない。

各 nb で最良の ib を選んだ値（5周の平均）:

| | 7月 最高 | 10/27 最高 | 倍率 | nb ごとの倍率 | nb_opt | 95%帯 |
|---|---|---|---|---|---|---|
| size 1024 | 4.8 GFlops（nb 172） | 94.8 GFlops（nb 96） | 19.6 | 中央値 13.5（8.8〜24.5） | 172 → 96 | 88-248 → 72-96 |
| size 2048 | 18.8 GFlops（nb 232） | 290.7 GFlops（nb 108） | 15.4 | 中央値 14.4（7.6〜24.0） | 232 → 108 | 168-312 → 96-140 |

- size 1024 で 1回 0.30 秒かかっていた。1コアで逐次に計算した見積もり
  （約 0.04 秒）より遅い
- 倍率は nb で一様ではない（nb 256 付近で約9倍、nb 32〜96 と 512 で20倍超）。
  曲線が横に平らになり、山が大きい nb 側へずれていた。この形を見て
  「最適 nb が大きい」と読んでいた
- 2026-10-27 に plasmatest を手で5回流すと、nb 176 / ib 44 で
  50.1〜63.3 GFlops（7月は同じ点で 4.6〜4.8）。再計測のスイープの
  nb 176（65.4）とほぼ合う
- 再計測は周ごとの全点平均が 1024 で 36.7、2048 で 124.3〜124.4 と
  そろっていて、点ごとのばらつき（CV）は中央値で約1%

**形の上では完走しているので、`make validate` も COVERAGE も拾わない。**
最高 GFlops を他の機械や同じ機械の別サイズと比べて初めて分かった
（同じ EPYC の size 4096 は 566.6、AOBA の size 1024 は約63）。

## 影響

2026-10-21 のゼミ資料（`analysis/2026-10-21/`）で「崩れる条件」とした
EPYC 7543 の size 1024 / 2048 は、この7月のデータによるもの。
再計測では予測が当たる（β=184.2、現行の c・k で 96.9% / 99.7%）。

## 再利用の条件

使わない。7月にだけ起きていた原因を調べるときの資料として残す。
